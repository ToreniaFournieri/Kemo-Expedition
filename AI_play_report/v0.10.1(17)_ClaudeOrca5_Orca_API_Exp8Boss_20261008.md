## Orca opening (the part another AI must not repeat blindly)
1. The Normal-mode opening fails. Ursan ninja/ranger snipers with Mirage had **0 usable returns** at 1f-3 and the first sortie was a Defeat. Starting inventory is tiny (+0 items) and gold is 200.
2. Orca's recommended-guide formation (Kemo guardian/sword-saint, Selfin pilgrim/wizard, Laika lord/alchemist, Lop ranger/pilgrim, Borg sage/alchemist, Grun wizard/alchemist, order `[1,5,6,3,2,4]`) is far better here, as is **God of Fortification** (twin: Fortification 8% return/1.5% defeat vs Mirage 2.5%/38% defeat at 1f-3). Hand-placed gear (4 gear moves plus a 3-item shop buy) took 1f-3 Return from 0% to 44%.
3. Level 1 farms ~50 XP/h. The 1f-3 elite gate needs 7 *consecutive* Returns (a Retreat resets the streak), so p matters a lot; after the gear fix the gate fell in ~1.5 days and D1's boss in 7.4 days.
4. I spent the 180 starting gold on the first shop lineup (wand, katana, bolt) before knowing which items mattered. A better first buy was probably sword/grimoire, as the guide says. Lineups rotate every ~8 h.

## What decided the run
1. **Deterministic optimisers beat the random hill-climb by a mile.** My `climb2` (random slot/swap/jewel moves) stalled at 2–5% gate success at D8 gate 4 for ~25 game days. `hpopt "1,6"` + `proxyopt "4,2,3,5"` (4 weight sets, pooled side-party gear `SIDE=1`) rated the **same save at 70%**, and D8 gates 4, 5, the boss gate and the boss then fell in about 3 days. I should have used it at every wall. `wall2.sh` runs it end to end.
2. **`proxyopt` needs a seeded attacker.** A character with no ranged/magic attack scores 0, so the greedy pass never starts (it printed `proxy 0 -> 0`). I patched it to seed arrow+bow (or wand+catalyst) first.
3. **Deity per wall**: Fortification early; **Fertility at D5** (twin 6% → 14% at the 5f gate, then used until the end). `deity_in_use` returns `heldByParty`; release with `party/N {deityId:"none"}`.
4. **Level cap is 40** (XP keeps counting past it). After Lv 40 only gear/deity levers remain; D8 gate 4 sat ~25 days at the cap before the pipeline fix.
5. **Attrition, not single fights.** `roomOnlyObjective` showed full-HP elite fights won ~100% while route success was 2–5%; carried HP decides. Use route-level rating (`lever.mjs`, `gateObjective`), not per-room scores.
6. **Boss fights**: kill rate once reached is high (≥ 70%); reach through 24 rooms (10–35%) is the limit. After the boss gate opens set `depthLimit all`, scan weights with `boss.py`, then `openopt4`.
7. An element-weight set that is too elemental hurts: `none`-heavy weights won at the D2 boss, `ice/thunder` at D4.

## Tips for another AI doing Orca +5
- Start: sign up with `environment:"orca"`, `gameMode:"orca"`, `levelOffsetForOrca:5`. Run Electron with `--environment=orca`. Use the guide's formation and Fortification, **not** the Normal-mode Mirage/Ursan formation.
- Look at the shop *before* spending the 200 gold; evaluate every allocation in the twin first. `ORCA=5` env now works in `ai_play_tools/twin` (`entry.ts` wraps `simulateExpeditionRuns` and `simulateApiSortieBatchForTesting`); the twin matched the live `simulationRun` exactly (100% Draw / 0% on the same save).
- Per gate, in this order: (1) set `depthLimit Xf-3` (`beforeBoss` for the boss gate, `all` for the boss), (2) `wall2.sh` (hpopt + proxyopt candidates rated with `lever.mjs`, apply best), (3) step 12 h (2 h for the boss), check the gate list.
- Watch the **streak rule**: Retreat/Draw/Defeat reset it. Gate p of 20–30% at a 5-gate is OK; 5% is not.
- Don't run `pkill -f` / `pgrep -f` with a pattern that also appears in your own command line (it killed my shell three times). Use `ps -eo pid,args | grep "^ *[0-9]* python3 …"`.
- Run long drivers with `nohup` in the background and poll with `until`/`for` loops. The worker restarted once in the middle of a 3 h driver; the game state was safe, only the Electron process had to be restarted (`logIn` again).
- An Orca save at Lv 40 gets ~2.3M XP per 12 h at D8; stepping further is pointless without gear changes.

## Opportunities for future runs
- Replace the random `climb2` in `gate.sh` with `wall2.sh` from the start (and prefer HP+attack plans per character). That alone would probably have saved 50+ days (D2 5f, D4 2f/boss gate, D5 4f/5f, D8 gate 4 were all >10-day walls).
- Add a deity lever scan (`lever.mjs` with all five deities) to every wall; Fertility at D5 was found only by hand.
- A route-level objective with smooth gradient (expected carried HP per room) is still missing; both `roomOnly` and `gateObjective` stall near zero success.
- Drop the 25-call build plans when the twin rating moves < 10 points; I applied about 60 plans, many of them marginal. The call budget is dominated by build calls (1,670) and by observation after every step (2,000).
- The unused gold (30k–50k) and the huge junk stacks (99× commons) were never sold or used. A sensible sink (shop refresh for enhanced items?) might help early walls.
- Check the Global Diary entry for `bossFirstClear` every block instead of the export (saves a call per block at D8).

## Bugs / issues / improvement requests
1. **`proxyopt` zero-start bug** (tool, fixed in the run's `ai_play_tools/twin/proxyopt.mjs`): characters without an attack never get one.
2. **`changeBuild` race collisions**: `ursan/female` was refused with `duplicate_race_and_gender` while another character already used it. The error does not name the holder. Equipment may silently be dropped when classes change (slot count 8 → 6 warns `equipmentSlotReduction`, but not which items fell out).
3. **A failed multi-call plan leaves the party half-equipped** (`removeEquipment slot_empty` mid-plan after a class change). A `plan`/`equipSet` endpoint or a dry-run would help (same request as earlier reports).
4. `GET read/observation/party` returned `experienceToNext` far beyond the Lv-40 cap (XP counts without effect). The cap is not mentioned in the API response or `Specification_9.1.3`.
5. `export` during a background driver sometimes failed silently (stale lease/revision), leaving no file. The client should return a non-zero status.
6. `drive`-style polling needs `chargeStock` and the Global Diary kill time in `read/observation/expedition` to detect a kill cheaply; the gate list alone cannot tell "open" from "defeated" (`[]` appears in both cases).
7. `Specification_9.1.3` says `Return` counts toward a gate only if room `X,3` was cleared — the wording in the Normal-mode reports is correct, but a **Retreat resets the streak** too, which makes the 7-gate at level 1 very costly; worth stating in the API guide for Orca.
8. Version metadata and `dist` staleness from earlier reports were not an issue in this checkout (build 17), but the build number is still not exposed by the API.
