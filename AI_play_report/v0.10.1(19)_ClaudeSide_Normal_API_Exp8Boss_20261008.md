## What decided the run
1. **`depthLimit Xf-3` works and is huge.** D6 gates 1–5 fell in 2.5 days with zero build calls. D8 gates 3, 4, 5 and the boss gate fell in 1.5 days after one plan. Do it from D1.
2. **The big loss: element immunity.** At D6 I applied a *thunder-weighted* `proxyopt` plan (+8 pts in the twin). At D7 room **3f-1** the enemy absorbed/nulled thunder: `roomfight` showed `dealt 0 / 19712` and every sim run was Draw/Defeat (`roomtab`: 3f-1 win 0/200). I stepped **12 blocks (6.5 days) blind** before looking. A `BAN=thunder` re-plan (`proxyopt` with `BAN=thunder`) rated 98.5% and the gate fell in 12 h.
   - Lesson: after a plan with one dominant element, check `roomtab` for any room with **win 0**, and never step more than 2–3 blocks without observing the gate counter move.
3. **Plans vs. no plans:** base ratings were 0–45% at D4 gate 1, D5 gate 5, D6 boss gate, D7 gate 3, D8 gate 2; the full plan (`hpopt` + `proxyopt`, 23–70 calls) took them to 79–99%. Build calls were 234 of 508 requests, so plans are the cost driver. An HP-only plan (4 calls) took the D4 boss kill from 31% to 77%.
4. **D8 was easy** once the plan was in (equal weights, rated 94% at gate 2). The boss gate opened at day 37.7 and the boss fell within 3 h.

## Tips for another AI
1. Use `play_runs/ai_play_tools/twin` + `pipe.sh`; on a fresh box: `npm ci`, `npm run build`, start with `xvfb-run -a node_modules/electron/dist/electron --no-sandbox scripts/run-api-play-session.cjs --environment=prod` (works headless, ~20 s).
2. Opening replay (all in the Fable ledger) costs 13 calls to D1 boss at day 1.25.
3. `loop2.py dest steps sec [x]` sets the depth limit from the gate list each block. Stops at boss-open unless the 4th arg is given.
4. `compact` is the cheap observation: both PT1's gate text and every party's `sideQuest`.
5. A gate list `[('godEntry'...)]` only = boss open; after the boss `[]`/`godGate` appears; confirm with an export.
6. `pkill -f run-api-play-session` inside a command that contains that string kills your own shell (hit me again). Use `ps | grep "[r]un-api..." | xargs kill`.
7. Before applying a plan with `thunder:2` weights, run `roomtab` for the next 2 dungeons' gate floors, or scan `BAN=` variants.

### Balance observations
1. **Frequency is very low and goes almost only to idle side parties.** The side-quest bag holds 1,287 "nothing" tickets and one ticket per quest (`src/game/bags.ts`), so a roll gives a quest with ~1% and each id appears **at most once per bag cycle**, which is why every total is exactly `/1`. Rolls happen only at the end of a `state.return` while the party has **no active Clear-Gate** (spec 5.1.2). PT1 was gated for nearly the whole run, so it got one quest (AFK) in 38 days. Since the reward is 1 jewel, the whole system is nearly invisible in a speed run.
2. **Healing (6) looks unachievable at high dungeons.** Code reading (`useGameState.ts`, `getApproxAfkTimeQuestProgressPerCycle`): it advances a fixed ~15 s of progress per cycle, while the target is 5–20 min (×1.3–2.0 for lv2–4) and the deadline is 16 h. With ~26 min cycles at D8 that is at most ~37 cycles ≈ 9 min. A live `q.healing-2: 0/8-16h/16h` was seen on PT2 and it was cancelled. Hypothesis from code, not separately verified. 0/3 observed.
3. **poor-kid (10)** (9 h limit, 10–30 ×1.3–2.0) and **treasure-super-rare (8)** (needs a super-rare drop within 24 h) were 0/3 each. These two are the shortest/rarest conditions; both look much harder than the others (squander, savings, AFK, exercise are 100%).
4. The `/cancelled` count does not distinguish an expiry from a God Battle cancel, so the 14 failures can't be attributed. Suggest separating `expired` from `cancelled` in the string.
5. Easy tier (100%): squander, exercise, AFK, losers, savings. Hard tier (0%): healing, poor-kid, treasure-super-rare, sleeping (1 sample).

## Bugs, errors and concerns
1. **Side-quest statistics cannot show frequency** (always `/1`) because of the one-ticket-per-id bag. Not a bug, but the field is almost useless for balance work; consider counting rolls or adding `lastAcceptedAt`.
2. **`read/observation/party?partyNumber=N` returns 404 `not_found` for unlocked-but-empty slots** (PT3–PT6 early). Expected; document which parties exist (`compact.partyInfo` lists them).
3. **`read/observation/diary` has no `scope` parameter** (400 on `scope=global`), but the response already includes the global entries under `global`. Document that.
4. **Global Diary** keeps the D8 `bossFirstClear` entry at the top (good). I did not check D3–D7 entries this time; Fable reported them missing.
5. **Gate list shows `[]` after a *Defeat* boss kill** while `disclosedOutcome` says Defeat (a boss kill in a run that then lost); confusing for pollers. Export check is still required.
6. **`changeExpedition` to a locked destination (D3 at day 3)** again returns `illegal_action`, now with no hint which gate is missing.
7. `pipe.sh` in the Fable folder had a hard-coded `cd`; fixed in this folder (`cd "$(dirname "$0")"`). `proxyopt` without `BAN` can choose elements that a later floor nullifies (see D7).
8. Build number is not exposed in the API (same request as Fable).
