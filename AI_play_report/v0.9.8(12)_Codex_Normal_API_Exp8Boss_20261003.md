## Advice for the next AI

1. **Use a viable opening immediately.** Lord/lord Kemo supplies Command 2, guardian/guardian Laika supplies Defender 2, and Ursan ninja/ranger snipers combine first strike with extra equipment slots. Keep a caster last because magic ignores row accuracy. These builds are a starting point; test changes against the current gate.
2. **Measure gate success, not boss clears, while a gate is closed.** A forecast capped at `3f-3` has no full clears by design. Read `depthLimit.reachable` and `blockedByGate`. Permanent gates need consecutive successes: floors 1–5 require 7/6/5/4/3, then the boss-entry gate requires 2 through 6f-3.
3. **Low success rates make streak gates very slow.** For independent success probability `p` and a required streak `k`, expected attempts are `(p^-k - 1)/(1-p)`. At k=5, p=0.30 means about 586 attempts; p=0.58 means about 34. Do a stronger gear/jewel search early instead of waiting several days at 30–40%.
4. **Stop after the boss, even if the optional Gods gate remains.** Once only `godGate` remains, the destination boss is beaten. Waiting for `clearGates=[]` can waste additional boss kills. Verify with a fresh `bossRare` diary log and the difficulty-offset maximum.
5. **Refresh both equipment and jewels at a wall.** `searchItems` with `state=owned` does not include jewels unless you request `category=jewel`. The optimiser's available pool must also include the main party's equipped items. Avoid counting equipment currently held by other parties as available.
6. **Stack distinct multiplier values and keep enough raw damage.** Repeated copies of the same c-bonus do not keep multiplying; distinct values/ranks do. Raw enemy defense is subtracted before damage amplification. Enhanced arrows and wands remain useful when their tier is low.
7. **Cheap vitality armor can be a major HP source.** Vitality changes the party's HP contribution from every equipped HP item. Try low-tier vitality pieces on the high-slot supports, while retaining sufficient physical and magical defense. Compare complete runs, not a character's defense alone.
8. **Re-test formation at each stage.** Command and Defender protect different rows, while ranged accuracy declines toward the back. Kemo first helped the third-floor refresh; Laika first was better for this fourth-floor and final route. Precision stayed preferable in our tested D8 cases. Other-deity offline tests assumed zero donation rank, so they do not establish a universal ranking.
9. **Choose elements for the current enemies.** D7's early gate preferred ice in this run; the fifth floor needed fire. D8 preferred thunder. A single element item can change the character's element, so avoid accidental conflicting elements in a greedy loadout.
10. **Use common seeds to compare offline proposals, then confirm with a larger sample.** Small seed-specific improvements can disappear in 1,000 runs. This run's third-floor search score fell from about 63% to 58.1% on confirmation. A few live forecasts can check the reconstructed model without paying for one after every trial.
11. **Preserve unchanged slots and jewels.** Build 12 supports `equip` with one item and `targetSlot`, replacing an occupied slot in one commit. Full rebuilds cost two calls per character plus every jewel attachment. This run still spent 245 calls on build commits; comparing gear as a multiset and making targeted replacements is the clearest call-saving improvement. For cross-character transfers, return needed copies/jewels before attaching them elsewhere.
12. **Separate progression from observation.** Advance in 12-hour blocks, checking every day during ordinary gates and every half-day near the boss. Small observations are cheap in duration but still count as API requests. Instant `sortie` charges can trade more calls for zero elapsed time when only a small number of successes remains; this run did not use them.
13. **Keep the control lease alive.** It expires after 15 idle minutes. The client now proactively logs in before a request after 14 idle minutes. Headless API sessions permit long offline CPU work without advancing game time; re-login may catch up the clock if it is behind wall time.
14. **Use fresh evidence IDs.** A retained diary log can be evicted after more progression. Our diagnostic request for a three-day-old defeat returned 404. Read the current diary before selecting a proof log. `read/observation/expedition` accepts no `partyNumber` in build 12; it returns the unlocked parties together.
