- the Slot2 formation (Laika guardian in front, Kemo lord, two Ursan ninja/rangers, a Leporian ranger, a Cervin alchemist/wizard);

- the deity changed at each wall: Mirage → Fortification (D4) → Fertility (D5); Precision at D8.

## What decided the run

1. **Batch sorties** (`numberOfSortie`) put the opening in about 60 calls. I did a sortie as soon as I had charges. Charges refill about 4 per 6 h.
2. **`depthLimit` is a free, large lever for the Clear-Gates.**
   - Spec 5.1.3.1 says a `Return` counts for a gate if the run cleared room `X,3`.
   - Setting the depth limit to `Xf-3` or `Xf-4` shortens the cycle and skips the X,4 elite.
   - D8 gate 5 sat at 0/3 for about 2 days, with plan odds of 10–15%. After one `changeExpedition … depthLimit "5f-3"` it passed within one 12 h block, and the boss gate fell shortly after.
   - **I found this only at the last gate.** It is probably worth days at D6, D7 and D8 gates 3–5.
   - The valid values are `1f-3`…`5f-4`, `beforeBoss`, `all`. `6f-3` is rejected (`invalid_depth_limit`). The boss gate still opened with `beforeBoss`. For the boss itself, put the limit back to `all`.
3. **Plans judged before applying.** Each wall followed the same loop: export, `pipe.sh` (`proxyopt` + `hpopt`, deity and weight scan), apply the best plan. The element weight set mattered. At D4 (boss) thunder-weighted gave 48% vs 14% for others. At D5 ice-weighted gave 93%. At D8 gate 2 thunder-weighted + Precision gave 47%. Equal weights won at D6.
4. **Don't sortie during a gate streak.** A sortie `Defeat` resets it. Sorties that `Return` do count toward the streak. This cost me one D4 streak and one D6 streak.
5. **Unique swaps were not worth it.** The twin rated Mishka and Sougaha on the caster at or below the baseline plan, so I skipped them (0 calls).

## Useful tips for another AI

1. Replay the opening: 5 `changeBuild` + one `party/1 {order, deityId:"mirage"}`, then `sortie {numberOfSortie:3}` at once, step 12 h × 2, `sortie 3`. D1 boss falls on the 3rd batch. The first `changeExpedition` to D2 returns `destination_locked` until a sortie Clear.
2. `elapsedSeconds` max is **43200**. Observe only every 2 steps. HP is full again after a 6 h step, so you don't need to look before sorties.
3. **Use `depthLimit` for every elite/boss gate** (above), starting at D4. Try it before spending 20–50 build calls on a plan.
4. Gate semantics: only `Clear`/`Return` count, and `Return` counts only if the run cleared room `X,3`. A gate list of `godEntry` only (no `bossGate`) means the boss is open. An empty list can mean open, closed or defeated, so check the export (`defeatedBossExpeditions`). The Global Diary also gives the exact kill time.
5. A cycle at D8 takes about 26 min. Boss clears at roughly 10% per cycle, so once the boss is open the kill comes within hours. Step in 6 h blocks with an export check, or use 2–3 h blocks if you want the exact stop time.
6. Plan loop: `pipe.sh <tag> <dungeon> <gate floor> "<weights>"` (copied from earlier runs; it takes the export and prints base/fort/fert/rest/prec for plans none/A/H/C). Scan 3–4 weight sets (fire-2, ice-2, thunder-2, equal) before applying. A plan is worth its calls only if it moves the rating by more than about 10 points; at D7 and D8 gate 6 the plan changed it by 5 or less and I skipped it.
7. `deity_in_use` now names `heldByParty` (build 4). Release the holder with `party/N {deityId:"none"}` then set yours. Precision is held by PT6, Fertility by PT3.
8. Do not `pkill -f run-api-play-session` from a shell command that contains that text; it kills your own shell.

## Opportunities for future runs

- **Use `depthLimit` from D4.** At D4–D8 I spent about 11 days (days 9.5–11, 15–20, 22–28) in elite-gate streaks that `Xf-3` limits would shorten. A combined run with the Sortie2/Slot2 plans could realistically reach D8 by day ~17–20.
- **Pick the weight set by gate, not by dungeon.** The best set changed at every wall (thunder, ice, equal, thunder).
- **Check the boss flag cheaply.** Poll `read/observation/diary` for the Global entry `bossFirstClear` instead of exporting, then stop within the same block.
- **Route-level attrition objective** is still missing from the twin. `roomfight` shows full-HP single rooms are won, while `roomtab` shows the loss is carried HP (3f-4, 4f-4, 5f-4 at D7/D8).
- Use sorties on the gate floor only when streak = 0; there are 6 idle charges most of the time after day 10.

## Bugs, errors and improvement requests

1. **Global Diary misses first-boss-defeat entries.** The Global tab lists `bossFirstClear` for dungeons 1, 2 and 8 only. Dungeons 3–7 are missing, although `defeatedBossExpeditions` shows them cleared. (D1/D2 were cleared by sorties early; D3–D7 were cleared by natural cycles, and D8 also by a natural cycle, so it is not simply sortie vs. cycle.) Expected: one entry per boss, as in changelog build 13/14.
2. **Diary keeps only 12 PT1 entries and no pinned Clear.** The first-clear battle log was gone after a few hours. Same request as earlier reports: pin the first Clear per dungeon, or expose `bossFirstDefeatedAt` and `logId` in `read/expedition/{p}/setting`.
3. **No `depthLimit` guidance anywhere in 9.1.3 / 9.1.4.** `validOptions.depthLimit` lists `6f-3`-style values for floors 1–5 only, but the Clear-Gate for the boss is "6F-3", so a user cannot select the exact depth the gate asks for. Either offer `6f-3` or document that `beforeBoss` is the equivalent.
4. **`sortie` stops the batch on the first `Defeat` but reports only the outcomes.** There is no `remaining` or HP in the response, so you cannot tell how many charges were spent or whether the party is empty. Add `chargeStock` and `currentHp`.
5. **`changeExpedition` to a locked destination returns `destination_locked` right after the boss Clear** (calls at D2, D3) — the unlock only applies after the next sortie/cycle is processed, one extra call. Document this, or evaluate the unlock when the boss falls.
6. **No build number in the API.** Version metadata is now aligned (0.10.1), but nothing in the API response says which build (17) is running, so reports must trust the checkout. Suggest a `buildNumber` in `fundamental/status`.
7. **Doc drift:** `Specification_9.1.3` does not say that `elapsedSeconds` has a 43200 maximum (the error is only `invalid_request … maximum`).
8. Non-200 responses: 1× `elapsedSeconds` 86400 (400), 4× `destination_locked`/`invalid_depth_limit`, 2× `deity_in_use`. No server errors this run (the earlier Diary 500 is fixed in build 16).
