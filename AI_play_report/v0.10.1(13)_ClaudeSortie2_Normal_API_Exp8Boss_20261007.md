Fresh `prod`/`normal` account, official API only, no imports, state edits or source changes. Not a controlled benchmark; one random stream. It is slower than Slot2 (29.5 d / 552) but faster than U1 (41.9 d) and with fewer calls than Slot2. The user asked for ideas for other AIs, not a score.

## Concept and what it found

Earlier reports left 3–6 Instant Expedition Charges (sorties) unused. **Concept "Sortie-Prime": spend the charges as free extra cycles.** Strategy was written to `STRATEGY.md` before signup.

| Finding | Evidence |
|---|---|
| Charges start at 3 and refill to the cap of 6 within about 12 h | chg 6 almost every observation |
| **Sorties are the cheapest EXP source early** | 6 D3 sorties = +31.7k EXP at Lv 19→20, versus 12.8k EXP for the whole run before that |
| Sorties pass elite-gate streaks instantly | D3 3f/4f gates cleared in 8 sorties (day 3.5–4.0); D1 gate 2/3 after one sortie |
| Value drops with level | twin EXP/run at Lv 23: D3 ≈ 250–500, D4 ≈ 1.6–1.9k |
| A Defeat sortie costs nothing in game time, but empties HP | one sortie per natural cycle is the useful rate; chaining sorties after a Defeat only returns `party_exhausted` |
| Sortie while a gate streak is running is risky | a Defeat resets the streak; I switched to no sorties during streaks |

Early milestones were faster than every earlier run: D2 boss day 2.75 (Slot2 4.5), D3 day 4.0, D4 day 6.25 (Slot2 9.25), D5 day 10.0 (Slot2 12.0). The gain came from sorties plus Mirage on the signup call plus `proxyopt` from D2. Later walls cost the same as before.

## What decided the run

1. **Element weights in `proxyopt` are a free 5–10x lever.** The same attacker optimiser with different element weights moved gate odds from 2% to 73% (D5 4f-4, ice) and boss damage from 0.46 to 0.64 (D6, fire:2). Scan 4–5 weight sets (`fire:2,ice:.5,thunder:.5,none:1`, ice-heavy, thunder-heavy, none-heavy, equal) and rate each with `lever.mjs … f` before applying anything. A default equal weight is often the worst. Cost is about 4 s per set.
2. **Find the first failing room with `roomtab.mjs save d f N [plan]`** (args: save, dungeon, gate floor, runs, plan). At D5 it showed 4f-4 elite (damage timeout `Draw`), not the gate floor. At D8 it showed 3f-4 attrition.
3. Deity: Mirage on the signup `party/1` call (no wait), Fortification D4 boss, Fertility D5 (release from PT3 with `deityId: "none"` first), Restoration at D6 reach, Precision at D7/D8.
4. Unique swap: Mishka (D6 start) and Sougaha (D7 start) on the caster. The Mishka refit gave a small gain at Lv 25 (18.4k → 18.7k metric), Sougaha gave caster M 1,115. Not a wall-breaker.
5. Gear plans were expensive: 240 of 531 calls were build calls (D5 plan 54, D6 51, D7 51). Plans re-gear whole parties.

## Useful tips for another AI

- Replay Slot2's opening, but put `deityId: "mirage"` into the single `party/1` order call at signup; it works on day 0.
- On every first day: sortie all 3–6 charges at the highest destination that returns `Clear`/`Return`; stop at the first `Defeat`/`Draw`. Re-sortie after every 6 h step while EXP matters (Lv < 28).
- Always **observe before sortieing**: my `sb.py` fired into `party_exhausted` and into 0-HP parties several times (about 15 wasted calls).
- Release unique with **`"uniqueSelection": "none"`** (string) in build 13. Boolean `false` now returns `400 type`; the U1 tip is outdated. Mishka is on PT4 char 301, Sougaha on PT5 char 402.
- `pipe.sh` (copied from U1, path-edit needed) does export, pstats, `proxyopt`, `hpopt` and lever sweep in about 4 s of compute.
- `hpopt` with a start plan fails (`item_not_owned`) if that plan was already applied to the live save: pass `none` as start on a fresh export.
- Loop helper: `loop.py N seconds sorties` steps and sorties in one script; `st.o()` prints all party gates.
- Kill check: gate list `[]` plus export `defeatedBossExpeditions[8]`. The kill entry is the `bossRare` diary entry; read it within 12 entries via `read/expedition/1/latestBattleLog?logId=diary:<id>`.

## Opportunities for future runs

- **Sortie EXP planner:** add a twin tool that prints EXP/run and Defeat rate for every destination at the current level so the AI picks the best sortie target automatically. I used D3 until Lv 21 and then D4 by hand.
- **Merge build calls.** A plan-diff that only changes slots whose item differs would cut 100+ calls. `planCalls` re-equips full characters.
- **Route-level objective for D8.** `gate` f=6 sits at 5%; a per-room attrition model (HP carried between rooms) would guide gear toward sustain. HP weights up to 2x pdef did nothing.
- **Level 31+ before D6.** D6–D8 all fell within about 2 days of a level jump (26→28 on days 13–14, 30→32 on days 20–26). More early EXP (more sorties, higher difficulty offset tests) is the lever.
- Keep sorties during walls only when HP is full and no streak is running.

## Bugs, errors and improvement requests

1. **`GET /read/observation/diary` returns `500 internal_error`** (requests 527–528) right after the D8 clear, every time. The same data is available only through the export. No other observation endpoint failed.
2. **Diary retains only 12 entries and no pinned Clear.** The kill entry survived only because the run stopped within 12 entries. Same request as earlier reports: pin the first Clear per dungeon.
3. **`GET /read/build/party/4` and `/read/build/character/301` return `404`.** Side parties and their characters can be edited (`changeBuild` on 301 works) but not read, so a unique's owner is found only by export. Add them to `read/build`.
4. **`unique_character_assigned`, `deity_in_use` still do not name the holder** (also U1/Slot2).
5. **API doc drift:** Spec 9.1.3 does not say that releasing a unique is `"none"`; U1's report said boolean `false`. A short sentence in the spec would help.
6. **`sortie` outcome `Retreat`/`Return` hides remaining HP.** The response lacks `currentHp`, so chained sorties are blind. Add `partyHp` / `partyMaxHp`.
7. **Gate counter semantic:** three consecutive `Clear` sorties at D3 moved a 3-streak gate only 0 → 1 (call 67). It is unclear whether Return/partial floors or the sortie path count differently. Worth documenting.
8. **Version metadata:** `app.getVersion` still reads `package.json` (0.9.8), as in Slot2.
