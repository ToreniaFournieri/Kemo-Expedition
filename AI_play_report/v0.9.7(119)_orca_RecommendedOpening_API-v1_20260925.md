* Floor 3 has a sharp difficulty spike. Enemy 112 鳳蝶 (thunder caster, first strike) wiped a Lv7 party holding 706 HP with three hits, before the party dealt any damage.
* The over-level EXP penalty makes progress slow. Measured gains were about 1,150 EXP/day at 2f-4, about 760 EXP/day at 3f-3, and about 1,100 EXP/day at 4f-3, where condition dropped to low/−240.
* Paid shop refresh doubles in price each time: 200, 400, … 51,200. Buying out the lineup raised intimacy from 0 to 61 and produced 1313 and 1314 (elite-rare shields). The shields had little effect in simulation.

## Notices (bugs, inconvenient behavior, and suggested improvements)

### Bugs

* **B1 (High): an API account saved in a non-ja language cannot be loaded.** After a fresh launch, `logIn` for the `en` account returns 500 `save_failed` with the message "Language dictionary is not loaded: en". The load path in `src/api/v1/sessionLifecycle.ts` never calls `ensureLanguageLoaded(accountState.global.language)`, and `setLanguage()` in the `App`/`HomeScreen` render throws. In the first launch, `signUp en` and `logIn` succeeded, but the next `read/observation/compact` never returned and `fundamental/status` then returned 503 `runtime_unavailable`. The renderer probably crashed in render from the same throw.
* **B2 (Med): renderer requests have no timeout.** `invokeApiV1Renderer` (`desktop/main.cjs`) sets a timeout only for `fundamental/status`. Any other request waits forever when the renderer does not answer. This was observed for more than 3 minutes.
* **B3 (High, auto-equipment logic): FULL auto-equipment produces characters with zero attacks.** It chooses per-hit attack or defense items (1111 grimoire at NoA −1, 1219, or armor) over owned catalysts and bows that add NoA. Observed results:
  * Laika at the opening: NoA 0.
  * Selfin, Laika, and Borg after 3h: NoA −1, −1, and 0.
  * Lop and Grun during AFK: NoA 0 and −1.

  FULL should never finish with no usable attack when an attack-preserving set exists.

### API issues and suggested improvements

* A1: 400 `invalid_request` "The request is invalid." has no `details`. This happened when `changeBuild` omitted `simulation` and when `purchaseShopItems` omitted `lineupId`. Errors should name the field and the reason.
* A2: `confirmation_required` is reported as generic `invalid_request` with `reason: "Error: invalid_request:confirmation_required"`, a stringified Error. It should have a dedicated code and include the warnings.
* A3: `changeBuild` with `simulation: true` returns only the build before the change. It gives no preview of the resulting stats or attacks.
* A4: `searchItems` defaults to `limit=10` and truncates silently, with no `totalCount` or `truncated` flag. Newly unequipped items were invisible.
* A5: Equipment arrays use `<slot>/<lock>/<itemId>/<enh>/<sr>` (5 fields), but inputs use Item Format (4 fields). Trailing empty slots are sometimes omitted.
* A6: `attacks[].available` is true even when NoA ≤ 0. `equip` should warn when a character loses all attacks.
* A7: `simulationRun` gives no hint when a gate makes the depth limit unreachable. It showed 99.9% "Success" for 3f-3 while every run stopped at 1f-4. `detail` always lists every floor through 6f+.
* A8: `simulationRun` reports only outcome percentages. Expected EXP, Gold, and drops per sortie or per hour would let clients choose a depth without 12-hour live A/B tests.
* A9: `sortie` returns `logId: "latest"`, not a stable ID.
* A10: Battle events are positional arrays (`compact-v1`) with no legend. `resources.rooms` repeats the same data in another schema. A short per-room summary would help diagnosis.
* A11: `sellInventoryItems` sells every copy of a variant and marks it `s.sold`, which enables auto-sell for future drops. It cannot sell N copies, and the side effect is not described at the endpoint.
* A12: The `autoEquipmentMode` field is numeric (1/2) in `read/observation/party` but `"SEMI"`/`"FULL"` in the `autoEquipment` commit.
* A13: Timezones are mixed. Diary `occurredAt` and `inGameTime` are UTC. `unreadDiaryTitle` timestamps are JST with no offset marker, and their text is percent-encoded (the spec example shows raw text).
* A14: `shopItemsList.current.items` uses an undocumented `<slot>/<itemId>/<price>/<available>` string that looks like Item Format but is not. `validOptions` also does not expose `lineupId`.
* A15 (minor): Float noise in ratios, for example 1.3599999999999999. `bottleneckEnemies[].cBonus` lists each bonus twice.

### Game and guide observations

* G1: The Recommended Opening guide is outdated. The `purchaseShopItems` example has no `lineupId`. `changeBuild` needs `simulation`. Its allocation (Borg with 1111 ×2) is not reproducible when the shop rolls only one catalyst. The opening is very sensitive to shop enhancement rolls: 0% success here with +1/+1/+1, against 45.8% in the previous report with +3/+2/+3.
* G2: With default settings a fresh party earns no Gold until a variant has been sold once. An attention hint would help, such as "inventory sale value 1,560G".
* G3: Floor 3 of dungeon 1 is a steep spike. Success fell from 92% at 2f-4 to 22% at 3f-4 at Lv7, driven by enemy 112's first-strike thunder volley. Kemo (kemoria, r.thunder 1.5) took 382 from a single hit.
* G4: Paid shop refresh price doubles without limit within a refresh window: 200 → 51,200 in 9 refreshes.
