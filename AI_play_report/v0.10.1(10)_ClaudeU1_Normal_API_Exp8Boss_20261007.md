### Unique-character concerns / possible bugs

1. **Duplicate name after release.** After `{"uniqueSelection": false}` on char 402 the character becomes a non-unique **named "Sougaha"** (race Lupinian, lineage `sandstorm`, predisposition `aggressive`); two characters then have the same name once Sougaha is assigned elsewhere. Suggest renaming the converted character (default-name table) as for race changes (Spec 8.2.3 default name assignment).
2. **Silent slot change.** The swap gave 10 slots (from 8) and left two empty slots, so the immediate result is *weaker*. The response `calculatedStatus` shows it, but a warning (`emptySlots: 2`) in the commit result would help AI/automation callers. Also `autoEquipment` is not triggered for SEMI parties.
3. **Opaque `unique_character_assigned`.** No `heldBy` party/character in `details` (same request as for `deity_in_use`).
4. **Side party interference.** Taking a unique from a side party requires a conversion call on that party first; it permanently converts that party's character (they are auto-equipped, so no real loss, but undocumented in the API spec).
5. **String vs boolean `false`.** Spec 9.1.3 writes `false` in prose; the 400 message should say "boolean false".

## What decided the run / lessons

1. **Per-character optimisers beat the generic GA again.** `proxyopt "4,2,3,5"` took D2/D4 boss odds from ~0 to useful at 8–32 calls. A boss-only GA gave no gain over `proxyopt` at D6 (0.44 vs 0.47).
2. **Deity lever depends on the stage:** Mirage D2 (applied late here, boss fell after gear plan instead), Fortification D4 boss, Restoration D5 boss gate (twin 18% → 53% with the HP plan), Precision best at D7 boss and D8 gates, Fertility needs PT3 to release it first (`party/3 deityId none`).
3. **Check the first failing room, not only the gate.** D6: 5f-4 elite (win 38/111). D8: 5f-1 `Zeke` (ranged ninja, 15k of 30k HP in one room), 5f-2, 6f-1/2, 3f-4. Fights from full HP were nearly always won; attrition across rooms decides, so party HP matters more than damage there (`hpopt` +1.5–5k HP).
4. **EXP is the hidden clock.** Lv31→32 needs 550k+ EXP (~66k per 12 h at D6). If a boss forecast is ≈0% at the current level, the cheapest plan is 1 call per 12 h with no observation, not more gear searching.
5. **Sorties are a gamble.** After a Defeat the party is exhausted (`party_exhausted`, 5 calls wasted looping), and a defeated sortie reset the D8 boss-gate streak 1/2 → 0/2 and left HP 0. Only use them when PT1 is at full HP and a single success finishes a gate.
6. **Difficulty offset for farming:** D5's cap is 64, but +24 is already 100% defeat and +6 yields less EXP than D6 at 0. Not a shortcut at Lv31.
7. zsh does not word-split unquoted variables: `set -- $cfg` loops silently broke my shell helpers; put loops in `bash` scripts (`pipe.sh`, `mdef.sh`).
8. `$S` shell variables do not persist between Bash calls; every command needs the workspace path.

## Useful tips for another AI

- Copy this flow: sign up, replay Slot2's calls 4–10 (class/race builds + order + Precision), step 12 h until `godEntry`, then run `proxyopt "4,2,3,5"` immediately (`SIDE=1`) before the first wall (not after). `pipe.sh` in the run folder (path-edit needed) does export → pstats → proxyopt → hpopt → deity levers in one go (≈2–4 min).
- Release Fertility from PT3 first; use `dmgplan.mjs` with `DEITY=` to rank deities on the boss before you spend a call, and `lever.mjs … f=7` with ≥400 runs to confirm.
- After D7 boss, release Sougaha from PT5's char 402 and give it to the caster (2 calls, +13%); after D5 give Mishka to the caster earlier (+29% at D6). Do it **before** D6, i.e. as soon as PT4 is unlocked, and refit with `proxyopt "5"`.
- Use an observation only every 2–3 blocks (`st.step(43200, False)`); overshoot only delays detection, not the kill.
- To verify the boss kill without the diary: export and check `parties[0].defeatedBossExpeditions[8]`; get the exact kill from the `bossRare` diary entry via `latestBattleLog?logId=diary:<id>` before 12 diary entries roll over.
