## What worked (tips for another AI)

1. **Large full-component GA is the main tool.** `populationSize 64, generations 200, quickRuns 300, confirmRuns 1000, timeBudgetSeconds 300`. It beats the presets by a wide margin, and a second pass often adds more. Real time is cheap (about 5 min per pass), calls are not.
2. **Use all components, not equipment and jewels only.** `equipment,jewels,mainClass,subClass,lineage,predisposition,raceGender`. Equipment-only GA left route and boss in conflict at D5-D7.
3. **Objective roles.**
   - `success` fixes the route (the gate and Return streak).
   - `bossDamage` raises the boss-only kill rate, but it wrecks the route (glass cannon: route 0-1 %, 1f-1 loses about 65 % HP).
   - `minDefeat` returns a 100 % Draw build, which is useless.
   - `experience` at 5f-3 gives a robust farm build (about 95 % success, about 2,100 EXP per run).
4. **Depth ladder when `success` is flat at 0 %.** A GA at 0 % has no fitness signal and returns `noisy 0 to 0`. Set `changeExpedition depthLimit` to 5f-4 or 5f-3 first (signal 40-87 %), apply, then set `all` and run `success` GA 2 or 3 times. `6f-3` is invalid (400), `5f-4` is valid.
5. **Level breakpoints.** Lv27 at D6 and Lv30 at D7 (a new slot opens). Farm with an `experience` GA at 5f-3 (a level costs about 12 game hours), then `success` GA right after the slot opens. At D7 route success went 0 to 81 % at 5f-4 and 42 % at `all`.
6. **Boss recipe.** Check `simulationRun` for `bossDamage` (boss-only) and `success` (route). Sortie when the route is at least about 10-25 % and the boss-only rate is at least about 75 %. The boss fell in 1 sortie at D7 and D8, 6 sorties at D6.
7. **`hl.py` loop.** K=3 sorties per cycle, HPF 0.97 (first sortie), HPF2 0.95 (extra sorties), one AFK cycle of elapsed with 90 s top-ups. `STOPCLEAR=0` for the farm, and a `godGate` in `clearGates` means the boss is down.
8. **D7/D8 time sinks.**
   - After the boss Clear the game keeps a `godGate` needing 3 Clears. I ran 24 extra Clear sorties at D7 for nothing, so stop at the first Clear if only the boss matters.
   - D8 elite gate floors 1 to 5 need streaks of 6 to 3 Returns, so the Return rate needs to be 85 % or more. Re-run the `success` GA at `all` whenever the streak stalls on a new floor.

## Staged tuning findings

- Acceptance was low: 10 of 78 (13 %). After a big GA it was almost never accepted (about 1 in 30), because the GA already holds the best element and resist set.
- Where it did help: early, before any big GA, or right after a slot opens, when the bottleneck room has a clear counter ability.
- The forecast `gain` often exceeded the live gate rate gain. The 7 % relative bar means it cannot pass once the forecast is high.
- Suggestion: allow `tuning` to run on top of a gaSearch result without replacing it, or report the bottleneck and counter candidates even when not accepted, so the AI can hand-pick them.

## Opportunities for future runs

- Go to the large full-component GA from D1. In this run D1-D3 used presets and time was lost there.
- Do not run `bossDamage` GA before the route is above 30 %. Do the `success` pass first, then verify the boss-only rate with `simulationRun`.
- Save calls: a `gaSearch` already returns before and after rates, so the extra `simulationRun` meter after each pass is mostly redundant (about 2 calls per pass).
- The farm for Lv27 and Lv30 is the dominant cost (about 6 days of game time). A stronger `experience` build earlier would shorten the run.

## Bugs, concerns, suggestions

1. **`gaSearch` objective enum lacks `progress`** (400), while `simulationRun` accepts it. Add it, or document why not.
2. **`changeExpedition depthLimit 6f-3` is rejected (400)** while `5f-4` and `all` are accepted. Please document the valid depth list per destination.
3. **`changeExpedition` to D5 gives 409 `illegal_action` until the D4 boss is cleared.** Expected, but the message could name the missing boss.
4. **`minDefeat` GA produces a 100 % Draw build and `applyBuildResult` applies it** (verdict was not `noisy`). Suggest warning or refusing when Success falls to 0 %.
5. **`success` GA at 0 % returns `noisy 0 to 0` with no hint.** A message such as "fitness is flat, try a lower depthLimit" would save a pass.
6. **`bossDamage` GA silently destroys the route** (route success 0-1 %). A route-floor constraint (for example a minimum success) would remove the conflict.
7. **A cleared boss keeps producing `Clear` sorties for the `godGate`**, so loops that stop on `Clear` do not stop. This is a design note, not a bug: the API could report "boss defeated" explicitly.
8. **Repeat of GA37 concern 2:** the API heals only per whole cycle, and streak gates need full-HP sorties. The D8 elite loop used many top-up `elapsed` calls.
9. **My own tool bug:** an env var named `EXTRA` leaked into `tune.py`, giving 4 HTTP 400s (`populationSize` unknown). Renamed to `GAX`.
