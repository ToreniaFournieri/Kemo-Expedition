## v0.10.1 character-build feedback

**Race:** Cervin and Felidian offer a meaningful damage-versus-initiative choice. Felidian's earlier action helped D6/D7 gates and D8's second gate once the pool was strong enough. It also produced many draws with an earlier D8 pool and was substantially worse at the fourth gate. A static recommendation to use either race everywhere would be misleading. Ursan remained a reliable slot-rich sniper base. A joint Vulpinian/Felidian sniper refit worsened D6 gate chances and was rejected; this was not an isolated test of either race. Unique Kemo and Laika remained useful. This run did **not** test ascension-unlocked race abilities, unavailable races, or late ascension balance.

**Class:** Ninja/Ranger's first strike and ranged package remained effective. Leporian Sword-saint/Ranger offered useful burst alongside the two Ninjas. Tested Ninja replacements for Lop generally underperformed the retained Sword-saint build. Alchemist/Wizard's attack count and accuracy floor justified keeping it; a same-gear Ninja/Wizard + Nimble caster trial was weaker at D8's fourth gate and had fewer slots, so it does not establish that the class is universally inferior. Preserve legal capacity and refit gear when comparing classes. Lord/Guardian on Kemo was tested locally at D8 gate 5 and did not improve the current build.

**Lineage:** Abyssal Sea remained a good ranged baseline. Utopia was useful for caster damage earlier. Oath became valuable late because it supplied the +2 slot source after Devoted was replaced by Nimble. This preserved eleven slots while adding speed. Oath with Perceptive or Inquisitive gave approximately **9.75–9.8%** fifth-gate Return on the proposed gear, versus **14.5%** for Oath/Nimble in the same 2,000-run seed. The practical value of a lineage depends on the trait and gear package, not its slot count alone.

**Predisposition:** Devoted gave usable extra slots to Leporian/Cervin/Felidian builds and was useful earlier. It should not be counted as another independent +2 source on a build already receiving that same slot bonus. Precise remained effective on Ursan snipers. Evasive's confusion protection did not compensate for lost offense in the tested D6 and D8 packages. Nimble was the strongest tested late caster option when paired with Oath. These are run-specific findings; the entire predisposition roster was not exhaustively balanced.

**Suggested build UX/API improvements:** Show the effective slot total with contributing and deduplicated sources; preview capacity changes and displaced equipment before a build commit; warn when a level-up creates empty SEMI slots; expose race-unlock prerequisites and active state clearly. A comparative preview including initiative, attack count, equipment multipliers and protection coverage would explain choices better than raw attack alone. These are usability suggestions, not observed calculation bugs.

## Useful tips for the next AI

1. Read the reports and record a strategy before signup. Reuse roles and mechanics, but derive equipment from the current owned pool.
2. Forecast the actual blocked gate. Optimize qualifying Return while capped; optimize full-route Clear once the boss is reachable. A full-HP isolated boss test ignores route attrition.
3. Check new slots immediately at levels 10, 20 and 30. SEMI upgrades occupied slots but does not fill a new empty slot for you.
4. Search **free inventory and all side-party equipment**. `notown` for a free-inventory item does not prove the account has no equipped copy.
5. Test race, initiative and formation together with damage. Ranged potency declines toward the rear; Command/Defender coverage can make a lower-sheet-damage formation stronger.
6. Use independent confirmation for rare outcomes. Small boss samples and damage surrogates overfit easily; rejected local searches saved live mutations here.
7. Export a fresh checkpoint before applying a plan if time has advanced. Automatic upgrades and side-party ownership can make old item strings unavailable. Dry-run the dependency resolver first.
8. Preserve items and jewel attachments. A proxy cost that ignores removal dependencies, jewel swaps and post-build exports understates actual calls. The eight-call D8 offensive refresh was preferable to a marginal twenty-call rebuild.
9. New side parties already default to FULL. Verify this before sending six redundant mode commits; the unconfigured PT6 equipped and farmed naturally in this run.
10. Refresh the control lease after a long planning gap, before a mutation. Keep credentials private and log every HTTP attempt, including failures.
11. **`godEntry` means the boss is still unbeaten; `godGate` means the boss was defeated but god prerequisites remain.** Empty gates can also occur. Verify the native boss flag and room-24 enemy-387 victory. Retain the exact diary immediately.
12. Fetch a retained diary with **`logId: "diary:<id>"`**. `diaryEntryId` is not a valid request property for `latestBattleLog`.

## Bugs, errors and improvement requests

**Confirmed version metadata mismatch:** `Specification.md` identifies v0.10.1 and `build_number.txt` is 1, but `package.json` still reports 0.9.8. The current source was rebuilt successfully before play. Synchronize package/runtime release metadata and expose an unambiguous version/build in API status or exported evidence. This run made no runtime fix.

**No confirmed combat or character-calculation bug was found.** Distinct slot-bonus behavior and SEMI's empty new slots were treated as mechanics, with the UX suggestions above. Gate projections behaved according to their source definitions; my initial interpretation of `godEntry` was wrong. Verification prevented an early stop.

**HTTP errors:** Call 190 returned `401 control_lease_expired` after a long planning gap; login and retry succeeded. This was expected lease behavior. Call 532 returned `400 invalid_request` because I passed `diaryEntryId` as a parameter; call 533 succeeded using `logId: diary:<id>`. This was a client mistake, not an API defect. More explicit examples in the retained-log documentation would help avoid that mistake.

**Local tooling mistakes, excluded from conclusions:** An early offline boss-gate key was wrong and was corrected before the later valid boss trials. Some offline faith trials used the nonexistent display name “Goddess of Fortification” instead of “God of Fortification”; those comparisons are invalid. An offline `sword_saint` identifier typo was corrected. Stale plans were rejected by dry runs, not attempted against live inventory. An HP memoization cache required replacing the characters array after in-place trial changes. The planner initially overlooked equipped side-party breaker arrows and underestimated jewel migration costs. These are AI tooling issues and should not be filed as game bugs.
