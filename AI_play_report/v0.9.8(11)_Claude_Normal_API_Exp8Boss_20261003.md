## What worked (reusable)
1. **`commit/setting/backup/export` = exact state for 1 call.** The file decodes with the repo's own `decodePersistedState` + `hydrateGameState`. Everything else (twin, planning, verification) hangs off this. It replaced ~130 read calls of run 4.
2. **Offline twin from the repo engine** (esbuild bundle of `src/hooks/useGameState.ts`). Seeds: replace `crypto.getRandomValues` (forecast RNG), `withGameplayRandomSourceForTesting`, `withBattleSeedSourceForTesting`. Forecast = live `simulationRun` (D6: twin 21 % vs live 29 % at one point; same build, different seed noise; D7 and D8 within 3 points).
3. **Optimise the exact stage probability, not a proxy.** Objective `k·ln P(success)` of the gate stage (+0.3·progress for smoothness) from `simulateExpeditionRuns` (N=120 quick, 400 confirm, common random numbers). D6 boss gate went 6 % → 21 % in one search; the sortie-based "progress" objective I used first plateaued at 7 %.
4. **Genetic algorithm beat hill climbing and annealing** (after the user asked for it): D7 boss objective −2.2 → +0.3 where 3 hill climbs sat at −1.8 to −3.5. Genome = items per slot + jewels, per-character crossover, pool-count repair, 3 mutation types, elitism, tournament selection, quick filter then confirm.
5. **Plan compiler**: `planCalls()` produces `removeEquipment` (per character) → one `equip` array **in ascending slot order** (the server fills free slots in order, so the layout is exact) → `jewelAttach/Remove` in dependency order; typical plan 9–20 calls. `replay.mjs` re-executes the plan on the twin to verify before spending calls.

Side quests only roll when the party has no open gate and give about one jewel per 100 returns, so total jewels by day 46 were ~12 (ranks 1–5). ## Bugs / gotchas found
* **`segment_cache_miss` → HTTP 500 `save_failed`** on `commit/progress/elapsed` (build 11). A large log object referenced twice in one saved state (`lastExpeditionLog` and a Diary entry) is sent as `{id,text}` then `{id}`; `encodeApiAccountSegments` only `remember()`s after `Promise.all`, so the second reference misses and the renderer retry cannot fix it. Local workaround in a snapshot of `desktop/api-save-encoder.cjs` (per-call `localPieces` map). Chip task created for the Coder.
* **Play Electron dies when idle.** After ~15+ minutes without API calls the renderer process disappears and `logIn`/`status` hang or return 503 (seen 3 times, also with `--disable-renderer-backgrounding`). `play_runs/ai_play_tools/client/ensure.sh` restarts it (login works at once afterwards; state is on disk). Also: `pkill` of the wrapper leaves the main process alive; two mains on one userData hang the API.
* `simulateApiSortieBatchForTesting` with `count>1` starts later sorties from the previous run's HP (stale `authoritativePartyStatus`): never use it for statistics; use fresh single-sortie calls or `simulateExpeditionRuns`.
* Forecast and AFK emulation agree once gates are held fixed; in a chain the first two `Return`s open the boss gate and later runs enter the boss room, which lowers `Return` counts (looks like a mismatch, is not).
* Item stacks cap at 99 and auto-sell; the pool only gains new variants.
* `read/base/shopItemsList` shows items up to the highest unlocked tier for 100–140 gold; a hundred of them is less than one step of drops, so I did not use the shop.
* Control lease dies after 15 idle minutes (`control_lease_expired` → `logIn`); the client retries automatically.

## Tips for the next AI
1. Follow `play_runs/ai_play_tools/README.md`; build the twin first, export every time before a search (1 call), never search on a stale state.
2. Use `OBJ=gate` for stage gates, `OBJ=bossonly`/`room` for single fights, `ALGO=ga`. Always `replay.mjs` the plan and check the exact stage report (`evalplan.mjs`) with a different seed before applying.
3. Apply a plan only when the forecast gain is large; typical plan 10–20 calls = about 1–2 steps of time.
4. Arrive at D8 with Lv34+, ~25k party HP and T7 shields; otherwise stay in D7 (3,100 XP/run) first. Watch `P(2F gate)` in the twin, not the dungeon number.
5. Step in blocks of 4–10 (`elapsed` 43200) and read `clearGates` once per block; remember the 15-minute lease and the Electron idle death (`ensure.sh`).
6. When you need fewer calls: keep plans small (`LAMBDA=0.005` in `wallopt3.mjs` penalises plan size).
