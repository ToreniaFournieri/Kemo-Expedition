## What decided the run
1. **Stalling for 2–4 days before rating** at D2 (misapplied `runplan2.py` path cost a block), D4 gate 2 (4 days), D6, D7. `loop2.py` stall detection (2 blocks) triggered correctly afterwards, but every wall still cost ~2 blocks first.
2. **Plans saved the walls**: D4 0% → 95%, D5 ~0 → 68%, D6 36% → 71%, D7 10% → 48%, D8 gate 5 11% → 24%.
3. **`depthLimit` carried gates 1–4 of D3–D8** with no build calls. D8 gate 5 and the boss gate fell in 1.7 days after plan C.
4. Level at D8 arrival was PT1 Lv30 (PT2 24, others lower); no EXP farming was needed because a 10-call plan was enough for gate 2.
5. Overshoot of the kill: polled in 3 h blocks, observed `[]` at 3 h; exact time from Global Diary.

## Tips for another AI
1. `open.py` and the D1 sequence: the sortie call returns 500 in build 27 but executes (see bug 1); do not retry it (charges are spent, retry gives `charge_insufficient`).
2. Rate plans **before** stepping a stalled gate: run `loop2.py` with stall=1 or rate at the first `Defeat/Retreat` repeat. Four days at D4 gate 2 were wasted.
3. `pipe.sh tag dungeon floor "weights"` with 3 weight sets in parallel (copy the export to `tag t`/`tag i` names). Floor = the gate floor that stalls (use 5 for the boss gate).
4. `[]` gate list after a boss: try `changeExpedition` to the next dungeon (200 = beaten, `destination_locked` = not).
5. Fertility (held by PT3): `party/3 {deityId:"none"}` then `party/1 {deityId:"fertility"}` (+16 pts at D5).
6. Do not pass `scope=` to `read/observation/diary` (400); read it unfiltered for the Global entry.
7. Copy `runplan2.py` into the workspace; `open.py` and `loop2.py` assume `t.py`'s `BOKEMO_PLAY_USER` is set.

## Opportunities for future runs
- Apply a plan the first time a gate shows `Defeat` twice in a row, or rate at every dungeon arrival (D4, D6, D7 each lost 3–4 days).
- A single combined plan C reused across the dungeon's remaining gates (D6, D8) avoided rebuilds; rate on the *last* gate floor rather than gate 2.
- Boss kill checks: poll the boss with 3 h blocks only when the odds are known; raise the block to 6 h if plan odds > 50%.
- Scan Fertility/Fortification only with `lever.mjs`; skip if gain < 10 pts.

## Bugs and requests
1. **Sortie 500 `internal_error` in build 27**: `commit/expedition/{p}/sortie` (both batches, `numberOfSortie` 1 and 3) executed but Electron logged `produced a response that does not match its catalog schema [{path:'', keyword:'required'}]`. State changed (charges 0, gate progressed). Earlier builds returned the sortie list; the response builder now omits a required field. Callers cannot see outcomes and retrying fails with `charge_insufficient`.
2. Gate list `[]` is still ambiguous (boss open vs beaten vs idle); a `bossDefeated` flag per party would fix it (same as SQ2).
3. Global Diary `scope` query parameter is rejected (400) while docs mention global entries in the unfiltered response only; document or accept it.
4. `loop2.py` did not stop on stall before this run (my tool); fixed, copy from this folder.
